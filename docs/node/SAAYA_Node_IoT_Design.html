SAAYA Node v1 — IoT heat-rest monitor and fan controller

Retrofit IoT product for outdoor-worker rest shades · Vellore, Tamil Nadu · VIT B.Tech CSE project · October 2026

1. Real-life scenario

Problem. Construction, road and farm workers in Vellore rest outdoors in pre-monsoon heat (May mean maximum ≈ 39 °C, record 45 °C). Typical rest sheds are bare GI or cement sheets that themselves run 55–70 °C, nobody knows whether the shelter actually helps, and a worker who feels unwell has no reliable way to call for help. India's NDMA draft cooling-centre guidelines (2025) ask for shaded rest structures for outdoor workers; SAAYA Node makes any such shade measurable and safer.

Users. Workers (press buttons, read the display), site supervisor / safety officer (receives help requests, acknowledges), site engineer (reviews logged evidence).

How it operates. The node bolts to the post of an existing shade. Every second it reads seat-zone air (SHT30 in a radiation shield), an outdoor reference (second SHT30), roof underside temperature (DS18B20), water availability (float) and the fan's real speed (tach) and energy (INA219). A worker presses MODE for the fan. In automatic mode the fan runs from 32 °C and stops at ≥ 39 °C, where published studies show a fan can add heat, and the display says so; manual control is never blocked. HELP latches a request (LED + 95 dB buzzer + OLED), survives power cuts, and can only be cleared by the staff ACK button on the side. Data go to a laptop over USB, or optionally over site Wi-Fi to the supervisor's dashboard.

Expected benefits. (1) A help request that cannot be lost or silently cleared. (2) Fault awareness: a stalled fan, dead sensor or stale data is reported, never shown as “cooling”. (3) Evidence: paired seat-vs-reference and roof readings prove whether a shade upgrade worked. (4) Very low energy: ≈ 34 Wh/day versus 11–13 kWh per shift for a 1.5-ton AC. (5) ≈ ₹5,314 per site instead of building a new ₹94k–1.7 lakh shelter.

Why this design fits. An open shade cannot hold AC-cooled air; shade + air movement + monitoring is the realistic intervention. The node is offline-first (control runs on the ESP32, not the cloud), cheap, weatherproof and retrofittable.

12 V input ≈ 271 mA typical (3.2 W), 578 mA peak (6.9 W), assuming 85 % buck efficiency. The 12 V 2 A adapter gives > 3× margin; the 1 A slow fuse clears a wiring short. Daily energy, fan 8 h + controller 24 h ≈ 34 Wh — a 20 W panel + 12 V 7 Ah battery could run it off-grid (option, not costed).

Design rules taken from the datasheets

  • IO34–IO39 are input-only with no internal pull-ups → external 10 kΩ on tach (IO34) and float (IO35).
  • 4-wire fan spec (Intel rev 1.2, Noctua): 25 kHz PWM; fan runs at full speed if the PWM line is undriven; tach 2 pulses/rev open collector → if the ESP32 crashes the fan fails on, not off.
  • DevKitC: power from USB or 5V pin, never both → USB only for programming.
  • INA219 bus ≤ 26 V; placed high-side in the 12 V fan branch only.
  • Two SHT30 share one bus via ADDR (0x44 low, 0x45 high); ADDR never left floating.
  • MP1584 IC is “not recommended for new designs” → fine for the prototype; MP2338 for production.

6. Deployment capability

Retrofit to an existing shade. Box centre 1400 mm (reachable seated or standing, above splash); seat sensor 1100 mm (seated head height); reference ≥ 2 m outside the shade at the same height; roof probe bonded to the underside centre.
ItemPlacement
Node boxShaded side of a post or wall, 1400 mm, glands down, drip loop under the box
Seat sensorIn shield beside the bench, 1100 mm, ≈ 0.4 m from the head, ≤ 2 m cable
Reference sensorIn shield on its own pole, ≥ 2 m from the shade edge, same height, ≤ 5 m STP cable
Roof probeBonded with thermal tape to the roof underside centre, shielded from direct sun
FanOn the post or a roof member, ≈ 1 m from the seat, 30–45° down
FloatInside the drinking-water can; wire leaves through the lid

Installation area

Construction or road-work site, farm, bus-stop or factory yard with an existing shade of ≈ 2.4 × 2 m for 4–6 seated workers; one node per rest shade. Larger rest areas (e.g. a 30–60 worker site with several sheds) use one node per shed.

Mounting

Four M6 anchors into a wall or two stainless hose clamps on a 40–90 mm post; no welding or drilling of the structure. Cables run in UV-stabilised conduit.

Power availability

Site 230 V socket → 12 V 2 A adapter kept in shade (≤ 7 W peak). Off-grid option: 20 W panel + 12 V 7 Ah battery (daily need ≈ 34 Wh).

Connectivity

Offline-first: all control on the ESP32. Data: USB serial to a laptop running the local API, or the optional Wi-Fi build (env esp32dev_wifi) posting each frame to the supervisor's laptop on site Wi-Fi with a device token; Wi-Fi runs in a separate task so a weak signal can never delay buttons or the fan. No cloud account or SIM needed; GSM/LoRa is a later option.

Environmental conditions

Shaded air 25–45 °C, monsoon rain, dust, 43–51 % afternoon RH in hot months. All parts rated ≥ 60 °C (ESP32, OLED −40…85 °C); IP65 box, glands down, breather vent; box and adapter kept out of direct sun.

Maintenance

  • Weekly: wipe radiation shields and fan guard; check float and water can.
  • Monthly: check gland tightness, cable chafe, fan tach vs. command on the display.
  • Quarterly: co-locate the two SHT30s for 20 min and record the offset; repaint/clean the roof top coat if soiled.
  • On fault: OLED states the fault (sensor / fan feedback / water); parts are plug-in and swap in minutes.

7. Operating logic, verification and online tools

Air < 32 °C, AUTOFan off (hysteresis: starts ≥ 32 °C, stops < 31 °C)
32–37 °C, AUTOFan 50 % PWM; display normal

≥ 39 °CAUTO fan stops (restarts < 38.5 °C); display “HOT: FAN MAY ADD HEAT”; MANUAL still allowed

Sensor missing / invalid“SENSOR FAULT”; readings unavailable (never zero); AUTO inhibited

Firmware stall5 s hardware watchdog restart; help latch restored

What has been verified

  • ESP32 firmware compiles in GitHub Actions (PlatformIO, espressif32 6.10.0).
  • Control logic: native C++ tests (latch, manual, fault, start-up grace, timer rollover, hysteresis, fan-benefit screen); identical rules tested in Python and JavaScript.
  • CAD: 23 solids valid, no interference > 1 mm³; STEP/STL exported.
  • Evidence API: 89 Python tests; browser tests on the public site.

Online tools used

  • Wokwi (ESP32 simulator): firmware/diagram.json wires the same pins to an ESP32-DevKitC V4, SSD1306, DS18B20, buttons, LED, buzzer and float switch. Wokwi has no SHT3x/INA219/fan part, so the simulation exercises the fault paths (sensor fault, fan-feedback fault, help latch). Prepared, not yet run.
  • GitHub Actions (CI compile + tests), Vercel and GitHub Pages (live 3D model and documentation), manufacturer datasheets and Indian shop listings (linked below).
Not yet proven: real air speed at the seat, sensor-shield bias, buck efficiency in heat, IP rating after drilling, and any health benefit. Next step: build two units, co-locate sensors, then run paired trials on three clear days.
